3. Детали по платформам

Vertex AI: Google опубликовал несколько заметных апдейтов: GA Gemini 3.8 Live с Live Avatar и блог о GKE agentic migration для AI‑assisted EKS→GKE миграций, а также анонс в блоге про лидерство Google в Gartner по контейнерному управлению (DP). Эти сигналы усиливают позицию Vertex по Prod-ops и по поддержке контейнерных/агентных рабочих нагрузок (CP): Google делает ставку на удобство миграции и управление кластером для агентных приложений, что снижает барьер у клиентов, переводящих агенты в облако. Для SL2 AI Platform это увеличивает конкурентное давление по части прод‑опсов и масштабируемости агентов (SP): наш G3 (Prod‑ops / распределённая трассировка) и G4 (FinOps / cost tracking) становятся более заметными недостатками у клиентов, рассматривающих managed‑вариант. Инвариант: сигнал -> критерий (Prod‑ops/scale) -> GAP (G3/G4) -> действие (ускорить observability и finops функции). Тест: отслеживать дальнейшие релизы Google по agent migration и детали интеграции с GKE (t).

Сигналы: Power your agents: Gemini 3.8 Live, GKE agentic migration for AI-assisted EKS-to-GKE migrations, Google is a Leader in the 2026 Gartner Magic Quadrant for Container Management.

AWS Bedrock: На неделе AWS опубликовал практические посты по масштабированию MoE RL на EKS, ускорению RL training на SageMaker, real‑time TTS deployment и, главное, паттерн «Build a multi-account AI agent with AgentCore Gateway and MCP» (DP). Это меняет позицию Bedrock по Indep. scale и Multi‑tenancy (CP): AWS демонстрирует архитектуры для масштабирования агентных нагрузок и ориентируется на мульти‑аккаунтный, безопасный доступ к данным через AgentCore Gateway + MCP. Для SL2 AI Platform это прямое конкурентное давление в двух измерениях (SP): managed‑поставщики делают интеграции и шаблоны для крупных организаций (G3/G4: Prod‑ops и FinOps), что подчёркивает наши незакрытые моменты по прод‑операциям и учёту стоимости работы агентов. Инвариант: сигнал -> критерий (Indep.scale, Multi‑account) -> GAP (G3/G4) -> действие (ускорить observability/cost tracking). Тест: отслеживать появление у AWS per‑agent cost/chargeback или microVM‑изоляции в официальных релизах (t).

Сигналы: Scaling MoE reinforcement learning on Amazon EKS, Build a multi-account AI agent with AgentCore Gateway and MCP.

Azure Foundry: Microsoft вывел в GA Routines в Foundry Agent Service (агенты, реагирующие на события и выполняющие продолжительные задачи) и добавил egress controls для hosted agents (DP). CP: Foundry усиливает возможности hosted agents для фоновых/routine‑задач и вводит сетевые egress‑политики — это улучшение прод‑опсов/губернанса у клиентов, использующих hosted‑агентов. SP: для SL2 AI Platform это сигнал, что облачные платформы развивают встроенные governance‑контролы и event‑driven агенты; наш G5 (data‑residency / self‑host observability) и G1 (Code+No‑code — отсутствие визуального билдера) остаются релевантными: клиенты, которым важна сетевой контроль и автоматизация, могут предпочесть облачные hosted‑фичи, если self‑host не даёт сравнимого уровня управления. Инвариант: сигнал -> критерий (Prod‑ops/governance) -> GAP (G5/G1) -> действие (оценить self‑host governance parity). Тест: смотреть документацию Foundry по сетевым политикам и adoption‑кейсам для regulated customers (t).

Сигналы: From Chatbots to Automated Agents: Routines in Microsoft Foundry Are Now Generally Available, Control where your hosted agent connects with network egress in Foundry Agent Service.

AutoGen (Microsoft OSS project): В репозитории прошли дискуссии и RFC по tamper‑evident audit trails, agent authentication, durable memory, и проблемы долгих multi‑agent run'ов (DP). CP: проект фокусируется на вопросах ответственности, аутентификации агентов и durable memory — это ранние стандартизирующие усилия вокруг межагентных взаимодействий и аудита. SP: для SL2 AI Platform это индикатор стандартизации потребностей в межагентной трассируемости и аутентификации агентов; нашиG3 (distributed tracing/observability) и G2 (Agent Protocol несовместимость с A2A) затрагиваются — если de‑facto библиотеки/стандарты оформятся, клиенты будут требовать совместимости и tamper‑evident audit trails, где у нас есть пробелы. Инвариант: сигнал -> критерий (observability/auth) -> GAP (G3/G2) -> действие (мониторить стандарты и готовить адаптеры). Тест: отслеживать финализацию RFC и появление reference‑implementations (t).

Сигналы: RFC: should AutoGen support tamper-evident audit trails, How are you handling agent authentication in multi-agent systems?, Proposal: optional durable memory via MemCode.

AgentForce (Salesforce): Публикации на этой неделе включают technical posts по pro‑code chunking для Data 360 и анонсы блюпринтов для commerce agents (DP). CP: Salesforce продвигает enterprise‑ориентированные практики (chunking, PII masking) и готовые шаблоны для коммерческих агентов, что снижает время внедрения. SP: для SL2 AI Platform это конкурентное давление в сегменте enterprise, особенно по быстрому запуску отраслевых агентов и встроенным best‑practices; это перекликается с нашим G7 (зрелость и экосистема) — у нас меньше готовых интеграций и marketplace‑предметов. Инвариант: сигнал -> критерий (Code+No‑code / developer ergonomics) -> GAP (G7) -> действие (ускорить отраслевые шаблоны / marketplace). Тест: мониторить появление готовых AgentForce starter kits и adoption кейсов (t).

Сигналы: Pro-Code Chunking of Data 360 Search Indexes for Agentforce, Build Agents Your Way with Claude and Commerce Cloud.

LangGraph / LangChain ecosystem: Релизы CLI/SDK (cli==0.4.32, langgraph==1.2.12, langchain core/openai updates) и изменение CLI, позволяющее "place self-hosted deployments on a listener" (DP). CP: проект продолжает развивать инструменты для self‑host и интеграции (улучшение developer UX и deployment опций). SP: это позитивно для self‑host экосистемы и может упростить жизнь клиентам, желающим собрать свои пайплайны на OSS‑базе; для SL2 AI Platform это частичное усиление конкуренции на уровне инструментов/операций (затрагивает G6 — мы изобретаем мультипровайдерную обвязку в SDK), но также подтверждает запрос на self‑host возможности, где SL2 AI Platform уже сильна. Инвариант: сигнал -> критерий (self‑host tooling) -> GAP (G6/G7) -> действие (оценить интеграцию с langgraph patterns). Тест: оценить влияние релиза CLI на adoption self‑host deployment сценариев (t).

Сигналы: langgraph-cli==0.4.32, langgraph==1.2.12, langchain-core==1.6.5.

n8n: n8n анонсировал n8n Agents — новый тип агента, который позволяет описать поведение агента, выбрать модель, инструменты и workflow, и также опубликовал материал по prompt testing и ряд релизов с фиксом OpenTelemetry export (DP). CP: n8n расширяет no‑code workflow‑платформу в сторону agent‑runtime, снижая порог входа для non‑dev команд. SP: это целенаправленная конкуренция по G1 (Code+No‑code — у нас нет визуального билда уровня Dify/Flowise), прямо усиливает пользовательскую альтернативу для менее технических команд; также улучшения OpenTelemetry трогают вопрос прод‑опсов (G3/G5). Инвариант: сигнал -> критерий (Code+No‑code / Prod‑ops) -> GAP (G1/G3) -> действие (приоритизировать визуальный builder MVP + OTel integration). Тест: отслеживать adoption n8n Agents и наличие enterprise‑кейсов (t).

Сигналы: Introducing n8n Agents, Prompt Testing Frameworks for Production AI Workflows, n8n OpenTelemetry fixes (releases).

NetBox: Сообщество активно обсуждает мобильный клиент, экспорт/производительность при экспорте, плагины и другие операционные задачи (DP). CP: это боковая активность сообщества по улучшению практических рабочих сценариев, но не меняет топологию конкурентов в AI‑space. SP: для SL2 AI Platform прямых импликаций нет — это сигнал зрелости сообщества NetBox, который не затрагивает наши GAPы; оставляем как н/п по критериям. Инвариант: сигнал -> критерий (community tooling) -> GAP (н/п) -> действие (не требуется). Тест: н/п.

Сигналы: NetBox Companion — mobile client, Way To Prevent Export From Causing Netbox To Freeze.

GLPI: Выпущен GLPI Agent v1.20 — инструментальные пакеты для агентов мониторинга/учёта (DP). CP: это полезный апдейт для пользователей GLPI, но не меняет ландшафт AI agent platforms. SP: для SL2 AI Platform н/п; не влияет на наши GAPы. Инвариант: сигнал -> критерий (инструментальный релиз) -> GAP (н/п) -> действие (н/п). Тест: н/п.

Сигналы: GLPI Agent v1.20.

CP: активность сообщества вокруг UX и интеграций; не меняет позиции в AI‑runtime сегменте. SP: для SL2 AI Platform н/п; это локальные улучшения линейки ITAM.
