3. Детали по платформам

Vertex AI: Google на неделе сделал несколько релизов и анонсов, которые усиливают их позицию как «full‑stack» поставщика AI (DP: Thomas Kurian keynote о full‑stack подходе, Antigravity SDK для agent hubs, AlloyDB Omni GA). Это меняет их профиль: они наращивают интеграцию платформенных компонентов (CP: усиливается Prod‑ops и интеграционные точки для agent‑ориентированных workflow и model‑hosting). Для SL2 AI Platform это означает усиление конкурентного давления по enterprise‑целостности стека и developer‑инструментам (SP: затрагивает G7 — зрелость/экосистема и частично G3 — Prod‑ops), но не меняет наше ключевое преимущество по self‑host для чувствительных окружений. Инвариант: сигнал → критерий (Prod‑ops/LLM routing) → GAP SL2 AI Platform (G3/G7) → действие. Тест: отслеживать релизы Antigravity SDK и интеграции Gemini Enterprise с Pub/Sub SMTs.

Сигналы: 3 Highlights from Thomas Kurian’s Keynote, Power agent hubs or custom harnesses with the Antigravity SDK, AlloyDB Omni RPM Orchestrator GA

AWS Bedrock: на неделе AWS опубликовал несколько материалов, фокусированных на production‑операциях multi‑agent систем: детальный подход к мониторингу жизненного цикла агентов с AgentCore Evaluations и AWS DevOps Agent (DP), а также материалы по latency/сaching (prefix‑aware routing) и метрикам стоимости/качества моделей. Это улучшает их профиль в Prod‑ops и Indep. scale (CP: Bedrock усиливает возможности по мониторингу, agent‑evals и оптимизации inference). Для SL2 AI Platform это прямое давление на наши незакрытые Prod‑ops/FinOps‑гепы — G3 и G4: managed‑конкурент предлагает встроенные agent‑evaluation и cost/trajectory‑метрики, которые покупатели ожидают в production (SP). Инвариант: сигнал → критерий (Prod‑ops/Indep.scale/FinOps) → GAP SL2 AI Platform (G3/G4) → действие. Тест: следить, появится ли у Bedrock per‑agent cost breakdown и GA SDK для AgentCore Evaluations.

Сигналы: Monitoring production agent lifecycle with AWS DevOps Agent and AgentCore Evaluations, Reduce LLM latency with prefix-aware routing on Amazon SageMaker Inference, Beyond the price per token: Choosing the right OpenAI model on Amazon Bedrock

Azure Foundry: в релизах Foundry отмечены улучшения speech LLM (multilingual accuracy, latency) и другие апдейты (DP: Announcing Azure AI Speech LLM 2607; What’s new in Foundry). CP: повышается производительность и пригодность Foundry для мультиязычных, latency‑чувствительных сценариев, что усиливает их позицию по Prod‑ops и LLM routing для speech‑сценариев. Для SL2 AI Platform это релевантно в контексте отраслевых клиентов с мультиязычными требованиями: давление на G3 (Prod‑ops) и G7 (зрелость) — мы должны мониторить, доступна ли схожая поддержка low‑latency speech‑inference в self‑hosted вариантах (SP). Инвариант: сигнал → критерий (Prod‑ops/LLM routing) → GAP SL2 AI Platform (G3/G7) → действие. Тест: проверять roadmap Foundry на self‑host/edge варианты speech LLM и доступ к model router updates.

Сигналы: Announcing Azure AI Speech LLM 2607, What’s new in Microsoft Foundry: July and August 2026

AutoGen: сообщество AutoGen активно обсуждает reproducibility, multi‑agent handoffs, deterministic safety и replay‑воспроизводимость (DP: обсуждения о replay без model server, RFC по SMT‑verification, handoff/authority receipts). CP: улучшается инструментальная база для разработки, оценки и воспроизведения multi‑agent workflows — это укрепляет экосистему open‑source runtimes и практик. Для SL2 AI Platform это индикатор роста community‑инструментов, которые потенциально облегчат миграцию/интеграцию приложений между рантаймами и повышают ожидания по reproducibility — задействует G7 (зрелость) и G3 (Prod‑ops) у нас (SP). Инвариант: сигнал → критерий (Prod‑ops/repro) → GAP SL2 AI Platform (G7/G3) → действие. Тест: отслеживать внедрение AutoGen‑инструментов в production‑кейсы и наличие миграционных гайдов.

Сигналы: Replaying an AgentChat run with the model server switched off, [[RFC] Deterministic Runtime Safety & SMT Invariant Verification for AutoGen](https://github.com/microsoft/autogen/discussions/8218), TMF: checking whether source context survives a multi-agent handoff

AgentForce (Salesforce): Salesforce объявила GA Web Console — современное in‑browser IDE, а также материалы по Data 360 кодовым расширениям (DP: Web Console GA, Data 360 code extension). CP: улучшение разработческого UX и governance внутри Salesforce экосистемы — упрощает создание/отладки agent‑приложений в их платформе. Для SL2 AI Platform это конкурентное давление в сегменте enterprise customers, у которых Salesforce — платформа стандарта де‑факто; это усиливает коммерческую привлекательность AgentForce для тех, кто ценит tight‑integration и low‑friction IDE, затрагивая G1 (Code+No‑code / порог входа) и G7 (зрелость экосистемы) у нас (SP). Инвариант: сигнал → критерий (Code+No‑code/dev UX) → GAP SL2 AI Platform (G1/G7) → действие. Тест: мониторить uptake Web Console в customer stories и наличие agent‑marketplace интеграций.

Сигналы: Announcing General Availability: Web Console – Your Modern In‑Browser IDE, Run Complex Data Transformations in Data 360 with Code Extension

LangGraph (langchain releases): в репозитории LangChain за неделю вышли несколько релизов пакетов (DP: релизы langchain-core, langchain-openai, langchain‑anthropic). CP: регулярные обновления укрепляют developer toolchain и интеграции с моделями, упрощая разработку agent‑workflow. Для SL2 AI Platform это влияние на ожидания по интеграциям и удобству разработки (SP: затрагивает G7 — экосистема/зрелость и Git‑native flows), но не меняет наш self‑host преимущество. Инвариант: сигнал → критерий (Git-native dev/tooling) → GAP SL2 AI Platform (G7) → действие. Тест: отслеживать новые интеграции langchain с self‑hosted model servers и MCP/MCP‑like протоколами.

Сигналы: langchain-core==1.6.3, langchain-openai==1.6.2

n8n: n8n опубликовал серию материалов по процессной оркестрации, reliability паттернам (Reflection), введению n8n Assistant и релизам с фиксом исполнения MCP toolkit на workers (DP). CP: n8n активно расширяет no‑code/low‑code orchestration для agent‑подходов и добавляет практики по self‑correction и production‑monitoring. Для SL2 AI Platform это прямое давление на наш G1 (Code+No‑code — отсутствие визуального билдера) и на G3 (Prod‑ops — паттерны для надежности/оценки агентов), поскольку n8n позиционируется как более простой вход для non‑dev команд (SP). Инвариант: сигнал → критерий (Code+No‑code/Prod‑ops) → GAP SL2 AI Platform (G1/G3) → действие. Тест: отслеживать adoption n8n Assistant и кейсы использования reflection pattern в production.
